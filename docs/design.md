# scifig design

scifig turns validated tabular data and an explicit figure specification into a publication-sized Matplotlib figure. Its first five templates—`learning_curve`, `benchmark`, `ablation`, `distribution`, and `heatmap`—share one styling, validation, layout, and export engine. Templates describe data semantics and choose artists; they do not own global plotting state.

## Rendering and style

Create a `matplotlib.figure.Figure` with an attached `FigureCanvasAgg`, and create axes through that figure. Use `matplotlib.rc_context` around both creation and export so settings used at draw time also apply, and restore the caller's settings on exit, including exceptions. Do not switch the global backend or use pyplot's figure registry. Matplotlib rcParams are process-global even inside a context: concurrent renders in threads must be serialized, or isolated in separate processes. See [the Agg example](https://matplotlib.org/stable/gallery/user_interfaces/canvasagg.html) and [rc_context](https://matplotlib.org/stable/api/_as_gen/matplotlib.rc_context.html).

Resolve a style into explicit dimensions in inches, font family and sizes, rc overrides, and a named color mapping. Offer configurable `single_column` and `double_column` widths rather than assuming a particular journal's rules. A category's color must come from a stable explicit mapping, independent of row order or which other categories appear; reject or clearly report unmapped categories. Curves additionally distinguish groups by line style or marker, and bars by hatch, to aid grayscale reading. Palette choices do not guarantee accessibility: authors must inspect contrast, print size, and their journal's requirements.

Use constrained layout for axes, labels, and colorbars; reserve room for legends and long labels. Avoid `bbox_inches="tight"` by default because it changes the physical output dimensions. If tight cropping or outside legends are offered, explicitly handle their layout participation and draw before export; otherwise artists may be clipped or alter the axes size. Do not combine `tight_layout` with constrained layout. Use axes-relative coordinates for panel labels and data coordinates for data annotations, choosing transforms intentionally. See [constrained layout](https://matplotlib.org/stable/users/explain/axes/constrainedlayout_guide.html), [transforms](https://matplotlib.org/stable/users/explain/artists/transforms_tutorial.html), and [artist structure](https://matplotlib.org/stable/tutorials/artists.html).

## Data and uncertainty

Validate configuration with Pydantic v2, parse YAML using `safe_load`, and normalize data to pandas/NumPy before rendering. Validate required columns, numeric and finite values, category order and mappings, bounds ordering, and incompatible choices with actionable errors. Inputs and units should remain visible and meaningful; do not silently drop invalid measurements.

No implicit aggregation: curve and bar cells must be unique when uncertainty is absent. Explicit `std`, `sem`, or `ci95` requests aggregate replicates as a mean and sample standard deviation (ddof=1), standard error (SD / √n), or normal-approximation interval (mean ± 1.96 SEM), respectively. Require at least two observations per cell, and warn that the normal approximation may be unsuitable for small samples, skewed data, or dependent observations. Precomputed lower and upper bound columns are an alternative to calculated uncertainty; require a unique central value and ordered bounds per cell and never reinterpret bounds as deviations. Clearly label uncertainty in figure metadata or accompanying documentation. The distribution template retains raw observations; it must not aggregate them away.

Learning curves plot x against y by series; benchmark and ablation compare categories using explicit ordering; distributions visualize raw observations by category. Heatmaps require a complete grid and reject duplicate or missing cells; heatmap aggregation is unsupported. Encodings, labels, normalization, and any aggregation remain inspectable in the specification.

## Export and limits

Export PNG for raster use and PDF/SVG for vector use with explicit size, resolution, and format. Select PDF Type 42 fonts when TrueType embedding is desired. SVG text can be paths for portable appearance or text (`svg.fonttype: none`) for editability, which depends on installed fonts. Rasterized image artists in a vector file remain raster images; output DPI controls their resolution. Fixed SVG hash salt and controlled timestamps can improve repeatability, but byte-identical output is not promised across Matplotlib, font, or platform versions. See [Matplotlib font handling](https://matplotlib.org/stable/users/explain/text/fonts.html) and [savefig](https://matplotlib.org/stable/api/_as_gen/matplotlib.figure.Figure.savefig.html).

Rougier's [Scientific Visualization: Python + Matplotlib](https://github.com/rougier/scientific-visualization-book) informs the emphasis on physical sizing, legible typography, restrained decoration, clear visual hierarchy, and deliberate use of color and coordinates. These are principles to adapt to the data, not a universal publication style. Inspect rendered output at its intended size; layout engines cannot determine scientific validity or guarantee legibility for every dataset.
